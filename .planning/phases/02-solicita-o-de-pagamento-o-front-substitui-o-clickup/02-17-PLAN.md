Criar `../financeiro-tria/automation/src/adapters/platform-adapter-queue.ts` exportando `criarFilaDeComandos(deps: { supabase; relogio?; maxTentativas? })` com:
  - `enfileirar({ taskId, operation, request, idempotencyKey })` — calcula `sequence` como `max(sequence)+1` para aquele `task_id` e insere com `status='pending'`. O `unique (task_id, sequence)` do banco é quem garante a ordem sob concorrência; um conflito significa recalcular e tentar de novo. O `unique (idempotency_key)` faz o reenvio do mesmo comando lógico não criar um segundo;
  - `reivindicarCabeca()` — seleciona, por `task_id`, apenas o comando de menor `sequence` com `status='pending'` e `available_at <= now()`, e só se **nenhum** comando anterior daquele `task_id` estiver `pending`/`running`/`failed`. Adquire lease por `lease_owner`/`lease_until`. Essa é a regra que impede status passar à frente do comentário e a que faz um comando falhado **bloquear** os posteriores da mesma Tarefa;
  - `executar(comando, adapter)` — chama o método correspondente; `ErroTransitorioDaPlataforma` → volta a `pending` com backoff (mesma escada do Plan 02-10: imediato; 5 s; 30 s; 2 min; 10 min; 30 min, com jitter); `ErroPermanenteDaPlataforma` ou `attempts >= maxTentativas` → `failed` com `last_error_code`/`last_error_summary` sanitizados; sucesso → `succeeded` com `response` (só os ids necessários para retomar o passo, nunca o DTO inteiro com documento e valor);
  - `aguardarResultado(idempotencyKey, timeoutMs)` — o serviço usa quando precisa do id do comentário para o passo seguinte. Se o comando não concluir no tempo, a função **não finge sucesso**: devolve `{ estado: "waiting_retry", comandoId }` e o chamador marca o run como aguardando, com referência ao comando;
  - `sanitizarErro(erro)` — a mesma disciplina do Plan 02-10: remove `Bearer`, padrões de CPF/CNPJ, chave Pix e query string, corta em 200 caracteres;
  - `comandosEmIntervencao()` e `reenfileirar(comandoId, quem, motivo)` — a superfície de replay manual exigida por D-20, registrando quem/quando/motivo.

Em `routes.ts`, preencher o ramo `plataforma` do seletor: `criarPlataformaAdapter({ baseUrl: requiredEnv("PLATAFORMA_BASE_URL"), token: requiredEnv("PLATAFORMA_SERVICE_TOKEN"), fila: criarFilaDeComandos({ supabase }) })`. O seletor continua sendo a única leitura de `PAYMENT_REQUEST_SOURCE`.

Criar `platform-adapter-queue.test.ts` cobrindo a Fault-Injection Matrix:
(g) API fora do ar → as quatro mutações ficam `pending` com `attempts >= 1` e nenhuma é perdida;
(h) FIFO: comentário, tag, vencimento e status enfileirados para a mesma Tarefa executam nessa ordem no servidor falso (conferir `recebidas`);
(i) comando 1 `failed` e comando 2 `pending` da mesma Tarefa → comando 2 NÃO executa;
(j) Tarefas diferentes avançam em paralelo (as duas cabeças são reivindicáveis ao mesmo tempo);
(k) `respostaPerdida` → o comando volta a `pending` e a segunda tentativa envia a MESMA `Idempotency-Key`;
(l) 429 e 503 → backoff cresce conforme a escada; 401 e 422 → `failed` imediato;
(m) duas instâncias de fila reivindicando a mesma cabeça → uma só executa (lease);
(n) `aguardarResultado` com timeout → `waiting_retry`, e o comando permanece `pending` (nunca `succeeded` falso);
(o) `sanitizarErro` remove token, CNPJ e query string.
