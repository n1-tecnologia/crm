Criar `../financeiro-tria/automation/src/http/webhooks-plataforma.ts` exportando `montarWebhooksDaPlataforma(deps: { service; supabase; tokenEsperado })`, um router Express pequeno montado em `/webhooks/plataforma`, com três rotas — `solicitacao-criada`, `comentario-criado`, `aprovacao-decidida` — e esta ordem obrigatória em cada handler:

  1. **Autenticar antes de qualquer parse**: comparar o `Authorization: Bearer` com o token esperado por comparação em tempo constante. Sem token ou token errado → `401` com o envelope sanitizado, **sem** ler o corpo;
  2. ler `Idempotency-Key` (que o worker da plataforma preenche com o `eventId`); ausente → `400`;
  3. validar o corpo contra o schema do evento (§8) — `zod` já é dependência do pacote; forma desconhecida → `400`;
  4. `insert into platform_event_receipts (event_id, event_type, task_id) values (...) on conflict (event_id) do nothing returning event_id`. Se **não** inseriu, o evento já foi recebido: responder `202 { accepted: true, duplicated: true }` **sem** criar um segundo run;
  5. se inseriu, criar/atualizar o run e só então responder `202 { accepted: true, event, tenantId, taskId }`. O processamento pesado é assíncrono, mas o receipt e o run são persistidos **antes** do 202;
  6. erro inesperado → `500` com envelope sanitizado e `requestId`; o detalhe vai para o log do processo.

Escrever uma função de erro **nova** neste módulo — `responderErro(res, code, requestId)` — que devolve `{ error: { code, message, requestId, retryable } }` com mensagens curtas e fixas. Não reaproveitar `handleError` de `routes.ts`: ele concatena `pg.message`/`pg.details`/`pg.code` e devolve isso ao cliente. Deixar `handleError` como está para as rotas antigas; nenhum comportamento existente muda.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → `/webhooks/plataforma/*` | qualquer um pode chamar; só a plataforma deve ser aceita |
| corpo do webhook → parser | parsear antes de autenticar amplia a superfície de ataque |
| 202 → outbox da plataforma | um 202 sem persistência faz o evento ser marcado entregue e sumir |
