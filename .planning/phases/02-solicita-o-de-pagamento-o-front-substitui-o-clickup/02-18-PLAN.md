  - `dto.fields.amountCents` → o campo de valor da forma interna (dividir por 100 uma única vez, no limite);
  - `dto.fields.issueDate`/`dueDate` → as datas internas, já em `YYYY-MM-DD`;
  - `dto.fields.supplierType`/`supplierDocument` → CPF/CNPJ interno;
  - `dto.fields.paymentMethod` + o campo coerente (`pixKey`, `barcode`, `pixCopyPaste`, `paymentLink`) → a forma interna de pagamento, incluindo `Cartão` → `link_pagamento`, que é o mapeamento que `payment-rules.ts` já conhece;

Nenhum fallback de nome alternativo de campo, nenhuma leitura da descrição livre da Tarefa para adivinhar valor, nenhum `try/catch` de parsing. Campo obrigatório ausente devolve erro claro e **sanitizado** (nomeia a chave do DTO, nunca o valor). Esse é o ponto: o mapper é curto porque o contrato é tipado.
