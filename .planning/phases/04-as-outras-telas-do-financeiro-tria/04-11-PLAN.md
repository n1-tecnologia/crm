Criar `dados/acoes.ts` com `"use server"` no topo. Uma função por ação, todas
devolvendo `{ ok: true } | { ok: false; erro: string }` — nunca lançando para a
árvore de renderização, porque uma exceção não tratada numa Server Action vira
uma tela de erro inteira no lugar de um `Toast`:

- `escreverNoFinanceiro(caminho, corpo)` — helper interno: pega o `access_token`
  como `leitura.ts` faz, `fetch` `POST` com `authorization: Bearer`,
  `content-type: application/json`, `cache: "no-store"`; traduz 401 em
  `"Sua sessão expirou."`, 403 em `"Sem acesso ao Financeiro."`, e qualquer outro
  não-ok no `error` do corpo (que o `apps/api` já devolve saneado).
- `salvarAliquotas(id, { porcentagemProduto?, porcentagemServico? })` →
  `/financeiro/produtos/${id}/aliquotas`, e `revalidatePath("/financeiro/produtos")`
  no sucesso.
- `executarWorkflow(key)` → `/financeiro/workflows/${key}/executar`. NÃO
  revalida: o `automation/` responde 202 e a corrida roda em segundo plano — a
  tela mostra o `Toast` neutro e quem decide quando reler é a pessoa, pelo
  "Atualizar agora" (D4-12).
- `importarPlanoDeContas(entrada)` e `removerLinhaDoPlanoDeContas(id)` →
  os caminhos de 04-10, com `revalidatePath("/financeiro/plano-contas")`. Ficam
  prontas aqui para a tela de 04-13 usar sem duplicar o transporte.
- `enviarExtrato` NÃO entra aqui: o upload precisa de progresso
  (`XMLHttpRequest.upload.onprogress`, UI-SPEC §5) e por isso sai do cliente para
  um route handler; é trabalho de 04-13. Registrar isso em comentário para
  ninguém procurar a função aqui.
  </action>
