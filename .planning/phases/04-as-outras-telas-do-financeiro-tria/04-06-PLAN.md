**`dados/leitura.ts`** (`import "server-only"` na primeira linha):

- `export type Leitura<T> = { readonly tipo: "ok"; readonly dados: T; readonly lidoEm: string } | { readonly tipo: "semSessao" } | { readonly tipo: "semAcesso"; readonly motivo: string } | { readonly tipo: "indisponivel"; readonly erro: string }` — os mesmos quatro de `EstadoInicial`, mais `lidoEm` (ISO do instante em que o fetch rodou), que é o que o "Atualizado há…" do UI-SPEC renderiza sem precisar de estado de cliente.
- `export async function lerDoFinanceiro<T>(caminho: string, query?: Record<string, string | undefined>): Promise<Leitura<T>>` — mesma sequência de `carregarEstadoInicial`: pega o `access_token` da sessão (sem token → `semSessao`); monta a URL com `process.env.API_URL ?? process.env.NEXT_PUBLIC_API_URL` + `caminho` + querystring montada por `URLSearchParams` descartando entradas `undefined`/`""`; `fetch` com `authorization: Bearer <token>` e `cache: "no-store"`; `catch` de rede → `indisponivel`; 401 → `semSessao`; 403 → `semAcesso` com o `error` do corpo; `!ok` → `indisponivel` com o `error` do corpo ou `O servidor respondeu <status>.`; ok → `{ tipo: "ok", dados, lidoEm: new Date().toISOString() }`.
- NÃO envolver em `cache()` do React: `cache()` memoiza por requisição e é o que `estado-inicial.ts` precisa porque é chamado duas vezes na mesma árvore; aqui cada tela chama uma vez, e memoizar esconderia o efeito do botão Atualizar. Registrar esse porquê em comentário.

**`dados/usar-revalidar-ao-focar.ts`** (`"use client"`):
- `export function usarRevalidarAoFocar(): void` — `useRouter()` do `next/navigation`; um `useEffect` que assina `visibilitychange` no `document` e `focus` no `window`, chama `router.refresh()` quando `document.visibilityState === "visible"`, e remove os dois ouvintes no cleanup.
