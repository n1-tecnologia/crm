Exportar `interface OpcoesDeFinanceiro { readonly cliente?: ClienteDeLeituras }`

No corpo, antes das rotas:
- Construir o cliente uma vez: `opcoes.cliente ?? criarClienteDeLeituras({ destinoUrl: process.env.FINANCEIRO_LEITURAS_URL ?? "", token: process.env.PLATAFORMA_LEITURA_TOKEN ?? "" })`. Este é o ÚNICO ponto do módulo que lê env.
- `async function comAlcance(request, reply, seguir)`: conecta em `pool()`, `hidratar(cliente, request.membro.workspaceId)`, e se `memberReachesContainer(state, request.membro.id, "folder", CP.folderId)` for falso responde `reply.code(403)` com `{ error: "Sem acesso ao Financeiro." }` — a mesma frase para todo mundo, sem dizer por quê (não entregar o mapa da permissão a quem não a tem). Com alcance, chama `seguir()`. `finally { cliente.release() }` sempre.
- `function responder(reply, resultado)`: `resultado.ok` → devolve `resultado.corpo`; senão traduz a falha do cliente em status do `apps/api`: `CREDENCIAL_AUSENTE` → 503 `{ error: "A leitura do Financeiro não está configurada." }`; qualquer outro erro → 502 `{ error: "O backend financeiro não respondeu." }`. O `code`/`summary` vai para `request.log.warn`, NUNCA para o corpo (T-4-11). Estas duas frases são as que a tela renderiza no estado de falha (D4-15), então são fixas e em pt-BR.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador (JWT do Membro) → `apps/api` | Entrada não confiável: query, cabeçalhos e a própria identidade alegada |
| `apps/api` → `automation/` | Credencial de serviço; a resposta do `automation/` é entrada não confiável para o `apps/api` |
