## Notas de planejamento

- `DATABASE_URL_MIGRACAO` entra no `api.env` de produção aqui com o mesmo valor do `DATABASE_URL` de hoje (o dono do banco); é inofensivo antes do merge (a versão no ar ainda não a lê) e é o que o backup usa. A troca de `DATABASE_URL` para `n1_api` é 09-20.
- O script do backup é instalado pelo root em `/opt/n1-crm/bin/` a partir da cópia do repositório (09-14), então o backup funciona antes de esta fase ir para a `main`.
- Se o Postgres do Supabase de produção for de versão maior que 16, a restauração usa `PG_IMAGEM=postgres:<maior>` (o espírito de D-21 é "descartável no Mac"; a versão segue o servidor — Pitfall 10).
